# 抽奖平台

> Domain: lottery-platform

美团外卖营销抽奖平台的领域知识，取自美团技术博客《领域驱动设计在互联网业务开发中的实践》中的示例系统：抽奖活动由运营在 M 端配置，C 端用户高频参与；一个抽奖活动包含多个奖池，奖池面向特定用户群体配置多个奖品，奖品带库存量与被抽中概率。

该领域以抽奖为核心上下文，并与活动准入、风控、计数、库存上下文协作：活动准入收拢开始/结束时间和参与次数等限制；风控限制用户参与频率；计数上下文为抽奖、风控与活动准入提供访问接口；库存负责奖品之外也可复用的库存核销。抽奖、风控、活动准入、库存与计数在文中的映射为合作关系；抽奖发券时通过防腐层隔离券码、平台券与外卖券等外部上下文。

本示例覆盖全部五种类型：5 个 Entity、1 个 Workflow、4 个 Rule、1 个 StateMachine、2 个 Event 页面。[用户参与抽奖](workflows/user-participation.md)描述协作顺序、发奖调用、响应转换和领奖记录；[用户参与抽奖事件](events/lottery-participation.md)与[奖品发放事件](events/award-issued.md)将原文中的业务发生建模为事件类型，展示参与对象及所属工作流，不假定原文存在独立事件消息实现。

原始文章没有定义生命周期状态与迁移。[抽奖活动生命周期](state-machines/lottery-activity.md)因此依据单独的虚构教学规格编写，页面链接到 `raw/demo-spec/` 中的明确来源，不将教学设定归于美团文章。它演示单个实体的状态变化，与跨对象协作的 Workflow 区分。
